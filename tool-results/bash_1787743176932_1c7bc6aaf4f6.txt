//
// Keys use a flat dot-notation namespace: `group.key`. This keeps lookup
// simple (one Record, no nested traversal) while still being self-documenting.
//
// When adding a new key:
//   1. Add it here first (English source of truth).
//   2. Mirror it in `hi.ts` and `gu.ts`. Missing keys fall back to English
//      at runtime via `useTranslation().t(key)` — but every locale should
//      carry the same set of keys so the fallback path is a safety net only.
//
// Translation scope: foundation only. Navigation labels, dashboard KPIs +
// section headers, common buttons (New / Export CSV / Save / Cancel), and
// the Settings card titles. Long-form descriptions (e.g. business-rule
// bodies) are intentionally left in English — they're rarely glanced at and
// translating them well requires domain copy-writing, not a key-by-key swap.

// `TranslationDict` is the type every locale's dictionary must match.
// Built from the shape of `en` (without `as const` so values widen to
// `string`) — this gives Hindi / Gujarati the freedom to supply any string
// while still enforcing that they carry the EXACT same key set as English
// (a missing or mistyped key is a compile error).
export type TranslationDict = { [K in keyof typeof en]: string };
